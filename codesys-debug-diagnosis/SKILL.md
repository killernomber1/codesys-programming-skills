# 调试与诊断系统化框架

## R — 原文（Reading）

> "CoDeSys 编程软件集成了 PLC 的仿真功能，可以实现使用 PC 仿真实际的 PLC 程序，应用在现场安装前，就可以进行完整的测试。"
>
> — 陆国君，《CODESYS 基础编程及应用指南》

---

## I — 方法论骨架（Interpretation）

CoDeSys 提供了一套从"轻量观测"到"深度分析"的五级调试体系，每级解决不同层次的诊断需求：

| 级别 | 工具 | 适用场景 | 是否需硬件 |
|------|------|---------|-----------|
| 1 | 在线监控 | 实时观察变量值、POU 执行状态、能流（LD 高亮） | 是 |
| 2 | 断点调试 | 程序停在指定位置，逐行检查变量和逻辑 | 是 |
| 3 | 强制变量 | 模拟输入条件，强制输出测试响应 | 是 |
| 4 | 采样跟踪（Trace） | 类似示波器，记录变量波形，导出分析 | 均可 |
| 5 | 离线仿真 | 无硬件时完整验证程序逻辑 | 否 |

**断点规则**（严格约束）：一个项目只能设置一个断点，且必须针对某个任务设置。断点可设在 ST 语言的赋值语句、RETURN/EXIT 指令、条件评估处和 POU 结束处。函数（FUN）/功能块（FB）内部不能设置断点。CFC 语言中仅在变量值变化位置或 POU 分支处可设。

**强制变量快捷键**：F7 = 强制值（锁死，即使外部信号变化也不改变）；Ctrl+F7 = 写入值（单次写入，不锁死）；Alt+F7 = 释放强制（解除强制值锁定）。

**采样跟踪（Trace）配置要素**：选择要记录的变量 → 配置触发变量 → 选择触发边沿（上升沿/下降沿） → 设置前置采样百分比（触发前记录多长） → 设置采样周期（基数和倍率） → 运行后波形自动绘制 → 可导出为 .txt 供 Excel 分析。

**仿真调试流程**：菜单"在线"→ 选择"仿真模式"→ 编译（无错误）→ 下载程序 → "调试"→ "启动"运行仿真。仿真模式下可执行在线监控、强制变量等所有操作，无需实际硬件。

**隐含检查函数（防御性编程）**：CoDeSys 系统预处理自动调用的安全函数，用于捕获运行时异常：

| 函数 | 保护对象 | 触发条件 |
|------|---------|---------|
| CheckBounds | 数组访问 | 索引越界（< 下界或 > 上界） |
| CheckDivInt / CheckDivReal | 整数/实数除法 | 除数为 0 |
| CheckPointer | 指针 | 空指针或无效地址 |
| CheckRange / CheckRangeSigned / CheckRangeUnsigned | 子范围变量 | 值超出声明的范围 |

这些函数并非用户手动调用——只需在应用中添加对应的隐含检查 POU 并编写处理逻辑（如越界时将索引限制在合法范围、除零时返回默认值），系统在对应异常发生时会自动调用。

**任务监视器**：在线->任务监视器可查看每个任务的平均/最大/最小循环时间，用于判断任务周期设定是否合理、是否存在异常抖动。

## A1 — 书中的应用（Past Application）

### 案例 1: 数组越界导致数据污染
- **问题**: 一个 100 元素的数组在生产运行 2-3 小时后出现异常数据，某些索引位置的数值被意外修改，但无法稳定复现。
- **方法论的使用**: 在应用中添加 CheckBounds 隐含检查函数，在越界时将索引拦截到合法范围并记录日志。添加后不久，CheckBounds 捕获到一个由计数器溢出导致的索引值 -32678，经分析是 CTU 计数器的 CV 值溢出为负数后直接用作数组下标。
- **结果**: 修改计数器数据类型为 DINT 并增加防溢出逻辑，数组越界问题彻底解决。CheckBounds 在处理完成前避免了 PLC 崩溃。

### 案例 2: 采样跟踪分析液压系统压力波动
- **问题**: 液压机在冲压过程中压力波动超过 15%，机械工程师认为是 PLC 控制周期过长导致调节滞后，要求缩短任务周期。
- **方法论的使用**: 使用采样跟踪功能配置压力传感器模拟量输入（IW）和 PID 输出（QW）为记录变量，触发变量设为压力上升沿，前置采样 30%。运行后分析波形发现压力波动周期约 120ms，而 PID 调节周期为 20ms（足以覆盖波动频率），波动根源是液压系统本身的机械振荡。
- **结果**: 用数据说服机械团队关注液压阀和蓄能器问题，避免了不必要的 PLC 周期调整。跟踪文件导出后用于供应商交涉。

### 案例 3: 现场调试用仿真模式预验收
- **问题**: 一套污水处理系统需在夏季雨季前上线，但硬件到货延迟 3 周，现场调试时间被严重压缩。
- **方法论的使用**: 硬 PLC 未到货时使用仿真模式进行完整的程序预调试：编写测试脚本模拟传感器信号（液位、流量、pH），强制变量模拟各种工况（正常进水/暴雨/设备故障），在仿真中验证了所有连锁逻辑和报警机制。
- **结果**: 硬件到场后仅用 2 天完成现场接线验证，程序一次性通过验收，整体工期缩短 60%。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 skill?

1. **程序行为异常（变量值不对/逻辑不按预期执行）**：需要登录 PLC 在线监视变量变化轨迹，判断是逻辑错误还是数据问题。信号词："在线监控"、"变量值不对"、"能流显示"、"程序在跑但输出不对"。

2. **程序崩溃或 PLC 进入 STOP（严重故障）**：需使用断点定位崩溃前的执行路径，或通过隐含检查函数捕获异常。信号词："PLC Stopped"、"程序中断"、"数组越界"、"除零"、"空指针"。

3. **I/O 信号测试与联调**：传感器/执行器接线完成后的信号校验、逻辑响应测试。需强制输入信号以模拟现场条件。信号词："强制输入"、"写入值"、"模拟传感器"、"F7 键"。

4. **量化分析与性能优化**：需记录变量随时间的变化曲线、分析程序循环时间瓶颈、优化任务周期。信号词："采样跟踪"、"Trace"、"波形分析"、"导出 Excel"、"循环时间分析"。

### 语言信号
- "程序跑飞了" / "在线看看变量" / "断点怎么设" / "强制输出" / "Trace 怎么配" / "仿真模式" / "CheckBounds" / "看门狗故障" / "任务监视器循环时间"

## E — 可执行步骤（Execution）

1. **建立调试环境**
   - 如无硬件：菜单"在线"→"仿真模式"，PLC 状态栏显示"仿真"标志。
   - 如有硬件：确保 PC 与 PLC 物理连接正常，通信参数（IP/波特率/站号）匹配。
   - 编译程序无错误后下载至 PLC（或仿真器）。
   - 完成标准: CoDeSys 底部状态栏显示"在线"（绿色），可直接展开变量树查看当前值。

2. **在线监控（Level 1）**
   - 登录后打开 POU 编辑器，变量值以黄色标记显示在变量名旁。
   - LD 梯形图可观察能流高亮（绿色连线表示逻辑通路导通）。
   - SFC 可观察步的激活状态（当前活跃步显示蓝色）。
   - 完成标准: 确认在线状态正常，变量刷新值符合预期，POU 执行顺序与设计一致。

3. **断点调试（Level 2）**
   - 注意：一个项目只能设置一个断点，且只能设在任务级别（不能在 FUN/FB 内设）。
   - 在 ST 代码行左侧双击设置断点（红色圆点）。
   - 触发条件满足时程序在此处暂停（黄色箭头指向当前行）。
   - 使用"单步执行"（F10）逐行推进，"复位"（Shift+F5）退出断点。
   - 完成标准: 程序可在断点处稳定停住，观察到的变量值支持逻辑推断。

4. **强制/写入变量（Level 3）**
   - 选中在线 PLC 中的变量 → 右键或使用快捷键：
     - F7：强制值（变量被锁定，外部信号无法改变）。
     - Ctrl+F7：写入值（单次写入，下周期可能被外部信号覆盖）。
     - Alt+F7：释放强制（恢复变量为程序写入值）。
   - 注意：强制变量时要确保不会引起设备不安全动作（如电机意外启动）。
   - 完成标准: 强制值生效且设备响应正确；Alt+F7 释放后变量恢复程序控制。

5. **采样跟踪 Trace 配置与分析（Level 4）**
   - 在应用对象中添加"采样跟踪"（右键 Application → 添加对象 → 采样跟踪）。
   - 配置步骤：
     a. 选择要记录的变量（最多 8-16 个，视版本而定）。
     b. 设置触发变量和触发边沿（上升沿/下降沿/双边沿）。
     c. 设置前置采样百分比（20%-50%：记录触发前的数据，便于分析问题根源）。
     d. 设置采样周期基数和倍率（总采样点数 = 基数 × 倍率）。
     e. 运行程序，触发条件满足后 Trace 自动记录波形。
   - 右键点击 Trace 可"导出为文本"，输出 .txt 文件，用 Excel 以 Tab 分隔符打开。
   - 完成标准: Trace 波形清晰展示变量变化趋势，触发位置标记准确，导出数据可在 Excel 中进一步分析。

6. **隐含检查函数添加（防御性编程）**
   - 在应用中右键"添加对象"→"隐含检查"→ 选择需保护的检查类型。
   - 编写处理逻辑（例如 CheckBounds 中将越界索引限制在数组范围内）。
   - 编译下载后，系统在运行时自动调用其检查逻辑。
   - 完成标准: 运行时若发生越界/除零/空指针/范围溢出，程序不崩溃而是执行预设的容错处理。

7. **任务监视器分析（性能诊断）**
   - 菜单"在线"→"任务监视器"或双击设备树中的"任务配置"→"任务监视器"。
   - 观察每个任务的平均循环时间（Avg）、最大循环时间（Max）、最小循环时间（Min）。
   - 判断标准：若 Max 接近或超过任务设定的固定周期时间 → 需优化代码或增大周期。
   - 完成标准: 所有任务在满负荷工况下的 Max 循环时间 < 固定周期时间 < 看门狗触发时间。

## B — 边界（Boundary）

### 不要在以下情况使用此 skill
- **程序架构设计阶段**：在代码未完成之前，调试技能无意义。应先完成编码和编译无错误，再进入调试阶段。
- **任务配置与实时性排查**：当问题本质是任务优先级、周期参数或看门狗设置不合理时，应使用"任务调度与实时性配置"技能，而非调试诊断技能。
- **通信协议故障**：Modbus/EtherCAT/CANopen 通信不通的问题应使用对应的通信配置技能。调试技能用于程序逻辑验证，而非网络抓包或总线分析。
- **运动控制参数优化**：轴抖动、跟随误差大、同步偏差等问题应使用运动控制调试工具（轴状态图/SoftMotion 分析器），而非通用变量监控和采样跟踪。
- **已部署生产系统上的危险操作**：强制变量和断点调试可能在生产环境中触发不安全动作。在生产系统上操作前必须确认安全隔离措施，或使用仿真/离线副本调试。
