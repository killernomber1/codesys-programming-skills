## 1. 结构（Structural）

### 类型
工业自动化编程技术手册 — 从零基础到项目开发的完整 CODESYS 编程指南

### 一句话主旨
以 IEC 61131-3 国际标准为主线，系统讲解 CODESYS 开发环境下的 PLC 编程语言、软件模型、指令系统、通信网络和工程实践，使读者掌握基于 CODESYS 平台的项目开发全流程。

### 骨架（主要论点及其关系）

本书按四大部分组织，共 15 章：

**第一部分：基础概念（第 0-2 章）**
1. IEC 61131-3 标准概述、软 PLC 技术背景、CODESYS 整体架构
2. CODESYS 软件模型：设备、应用、任务、库文件、POU（程序组织单元）

**第二部分：编程语言语法（第 3-6 章）** ★ 核心重点
3. 公用元素：字符集、关键字、注释、常数
4. 变量系统：数据类型（标准/扩展/自定义）、变量声明、命名规范、初始化
5. 六种编程语言：IL（指令表）、LD（梯形图）、FBD（功能块图）、ST（结构化文本）、SFC（顺序功能图）、CFC（连续功能图）
6. 指令系统：位逻辑、定时器、计数器、数据处理、运算、数据转换

**第三部分：开发实践（第 7-10 章）**
7. 程序结构：系统/用户程序、常用编程方法
8. 基础编程：编译、下载、在线监控、调试、仿真、PLC 脚本
9. 可视化界面（HMI）：控件、工具、视图建立
10. 常用库函数介绍

**第四部分：工程通信与实例（第 11-13 章）**
11. 控制系统工程实例：圆盘控制、火警、抢答器、交通灯、停车场、恒压供水
12. 通信网络：CANopen、Modbus（RTU/TCP）、EtherCAT、PROFINET、EtherNet/IP
13. 附加功能：程序安全（加密/用户管理）、诊断及常见故障

**附录（第 14-15 章）**
14. 快捷键
15. 参考文献

**论点之间的关系**: 递进式 — 从概念到语法到实践到通信，层层深入。第二部分是全书重点（约占 60% 篇幅），第四部分为综合应用。

## 2. 解释（Interpretive）

### 关键术语（作者本人的用法）

| 术语 | 作者的定义 | 和常识用法的差异 |
|------|-----------|----------------|
| **POU**（程序组织单元） | 用户程序的最小软件单元，由声明区+代码区组成，分函数(FUN)、功能块(FB)、程序(PRG)三种 | 不同于普通编程语言的"函数"概念，POU 是 PLC 特有的组织方式，功能块有内部状态和实例化概念 |
| **软 PLC** | 用 PC 或嵌入式控制器作为硬件平台，用软件实现硬 PLC 的功能 | 不是"软件模拟"，而是实时核+编译器的真实控制系统，可达到硬实时 |
| **任务** | 控制程序执行方式和周期的配置对象，可配置循环/事件/触发/系统事件四种类型 | 不同于 OS 的任务概念，PLC 任务是"程序调用容器"，决定何时执行、优先级和看门狗 |
| **库文件** | 存放可多次使用的 POU、数据类型和全局变量的集合文件 | 不是 DLL/so 那种二进制库，而是高层的功能模块容器，有加密库(.compiled-library)和标准库(.library)之分 |
| **实时核** | 对操作系统进行实时性改造的内核扩展，保证微秒级抖动量的确定性 | 不是独立的 RTOS，而是对 Windows/Linux 等非实时 OS 的实时扩展补丁 |
| **看门狗** | 监控程序执行异常的计时器，超时则中止任务 | 有"灵敏度"参数（允许连续超时次数），触发时间=时间×灵敏度 |
| **访问路径** | 用于将全局变量、直接表示变量、功能块 I/O 和局部变量联系起来的机制 | 对用户透明，无需手动操作，自动在后台完成 |
| **CFC**（连续功能图） | 自由放置功能块和连接元素的图形化编程语言，执行顺序由数据流决定 | 区别于 FBD（按网络顺序执行），CFC 可自由放置且支持反馈路径 |

### 核心命题（用自己的话）

1. **IEC 61131-3 是 PLC 编程的通用语言标准**，打破了各厂家编程互不兼容的局面，让程序具备可移植性
2. **软 PLC 技术以软件替代专用硬件**，用 PC/嵌入式平台 + 实时核实现传统 PLC 功能，兼具开放性和可靠性
3. **CoDeSys 提供 6 种编程语言**（IL/LD/FBD/ST/SFC/CFC），可在同一项目中混合使用
4. **POU 是 PLC 编程的基石**，分函数（无状态）、功能块（有状态需实例化）和程序（主入口）三种
5. **变量系统非常完善**，支持标准类型、扩展类型和自定义类型（STRUCT/ENUM/ARRAY），含全局/局部/输入/输出等多种访问层级
6. **任务系统决定程序执行行为**，可配置循环周期、事件触发、优先级和看门狗
7. **库文件机制支持代码复用**，包括系统库、应用库和厂商自定义库
8. **CoDeSys 支持多种工业现场总线**：CANopen、Modbus、EtherCAT、PROFINET、EtherNet/IP
9. **软件模型是分层结构**：配置→资源→任务→POU，一层层向下精化
10. **可视化 HMI 可直接在 CoDeSys 中开发**，无需外部工具
11. **运动控制功能已集成**（SoftMotion/CNC），基于 PLCopen 标准
12. **安全 PLC** 已获 TUV 认证，可开发 SIL2/SIL3 安全系统

### 论证链
作者从国际标准（IEC 61131-3）出发 → 引入软 PLC 概念 → 落脚到 CoDeSys 实现 → 逐层展开软件模型 → 深入编程语言语法（核心） → 讲解开发调试流程 → 最后结合通信网络和完整工程实例收尾。全书遵循"原理→语法→实践"的三段论教学逻辑，每个章节都有示例代码支撑。

## 3. 批判（Critical）★

### 作者的时代局限
1. **基于 CoDeSys V3.5 SP4（2015 年前后）**，当前 CODESYS 已发展到 V3.5 SP19+，界面、功能、库文件有较大变化
2. **2015 年的工业通信主流是 CANopen/Modbus**，当时 EtherCAT 刚起步，现在已成为主流；书中对 OPC UA、MQTT 等现代通信协议未涉及
3. **未涉及 IoT/工业 4.0/数字孪生**等当下热门主题
4. **安全 PLC 部分仅提概念**，当时的安全标准（EN 61508）和章节都较简略
5. **人机界面（HMI）技术**在 2015 年后有了 Web 化、移动化的巨大发展，书中仍以桌面 HMI 为主

### 作者的立场盲点
1. **从零基础初学者视角出发**，对高级用户（如性能优化、复杂运动控制、自定义库开发）覆盖不足
2. **作者可能来自教育或培训背景**，书中偏重语法讲解和教学示例，对实际工程中的坑（如实时性问题、总线抖动、掉电保护）涉及很少
3. **大量篇幅给梯形图（LD）**，在现代工程中 ST 和 CFC 实际使用率更高
4. **对代码组织规范和团队协作**几乎没有讨论

### 未被证明的假设
1. 假设读者对 PLC 基础有基本了解（未涉及硬件接线、传感器/执行器选型）
2. 假设 CoDeSys 平台本身稳定性无问题（实际工程中版本兼容、库冲突等很常见）
3. 假设中文读者能顺畅理解直译的技术术语（部分翻译不够标准）
4. 假设所有硬件厂商的 CoDeSys 平台实现完全一致（实际各厂家的实时核实现和库文件差异很大）

### 最强反对意见
本书更像一本"语法参考手册 + 入门教程"的合集，而非真正的"项目开发指南"。真正的工程实践（如代码版本管理、单元测试、CI/CD、安全规范落实、性能调优方法论）几乎没有涉及。如果要训练一个能真正帮助工程师写 CODESYS 程序的 agent，这些高质量工程实践内容比 6 种语言的语法细节更重要。
