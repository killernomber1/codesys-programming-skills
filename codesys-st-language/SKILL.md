# ST 语言编码与混合选型

## R — 原文（Reading）

> 在实际的工程项目中，涉及算法部分请选择 ST 语言；涉及流程控制部分请选择 SFC 语言；涉及逻辑控制部分请选择 LD 语言；涉及功能块部分请选择 CFC 或者 FBD。
>
> ST 语言程序与通常的 PC 编程语言类似，利用指令语句编写的程序段可以完成复杂算法的控制功能。ST 语言同样可以进行条件语句的选择（IF...ELSIF...ELSIF...ELSE...END_IF）和循环语句的执行（FOR 循环、WHILE 循环和 REPEAT 循环）。
>
> CFC 语言中元素的执行顺序可以从左到右、从上到下（拓扑排序）或按数据流顺序执行。数据流排序的优点是：一个算法执行后，连接到它的输出引脚上算法块会立刻执行。
>
> — 陆国君

## I — 方法论骨架（Interpretation）

### ST 语法核心要点

1. **赋值语句**：`变量 := 表达式;`。与 IEC 61131-3 一致，用 `:=` 赋值，语句以分号结尾。

2. **条件分支**：
   - `IF 条件 THEN ... ELSIF 条件 THEN ... ELSE ... END_IF;`
   - `CASE 表达式 OF 值1: ... 值2: ... ELSE ... END_CASE;`

3. **循环结构**：
   - `FOR 变量 := 初值 TO 终值 BY 步长 DO ... END_FOR;`
   - `WHILE 条件 DO ... END_WHILE;`
   - `REPEAT ... UNTIL 条件 END_REPEAT;`
   - `EXIT`：立即退出当前循环。

4. **函数/功能块调用**：
   - 函数调用：`result := FUN_MyFunction(input1 := val1, input2 := val2);`
   - 功能块调用：需先实例化 `fbMyBlock : FB_MyBlock;`，然后 `fbMyBlock(input1 := val1, output1 => outVar);`
   - `=>` 连接功能块输出到变量

### 六种编程语言混合选型矩阵

| 场景 | 推荐语言 | 理由 |
|------|----------|------|
| 复杂算法、数学运算、数据处理 | **ST** | 文本化、可读性强、适合高级逻辑 |
| 流程控制、工序管理、顺序逻辑 | **SFC** | 步-转移-动作模型清晰，条理分明 |
| 逻辑联锁、互锁、简单开关量 | **LD** | 电气人员直观理解，梯形图可视化 |
| 功能块组态、信号流 | **FBD** | 图形化网络清晰易读 |
| 大规模连续控制、自定义执行顺序 | **CFC** | 自由放置、数据流排序、反馈路径 |
| 底层操作（V2 兼容/简单逻辑） | **IL** | 对应 LD 的文本版本，现代工程中已较少使用 |

### CFC 执行顺序简要说明
- **拓扑排序（默认）**：按元素坐标从左到右、从上到下编号执行。位置固定，易于预测。
- **数据流排序**：按数据连接关系排序，输出信号直接传递给下游块立即执行。符合算法直觉，但变更连接后顺序可能意外改变。
- 手动调整工具：置首、置尾、设置执行顺序编号。
- 建议：有明确数据依赖的复杂算法用数据流排序；简单逻辑用拓扑排序保持稳定。

### 核心原则
**同一项目可混合使用多种语言**，同一 POU 内使用一种语言，不同 POU 可用不同语言。避免用单一语言解决所有问题。

## A1 — 书中的应用（Past Application）

### 案例 1: 交通灯信号控制 — SFC + ST + IL 混编
- **问题**: 交通灯控制需要多阶段时序切换（东西绿灯 20s -> 黄灯 3s -> 南北绿灯 10s -> 黄灯 3s 循环），同时涉及信号状态分配算法和计数器统计。
- **方法论的使用**: 主程序用 **SFC** 编写状态机（步 + 转移条件驱动 5 个状态循环流转），功能块 `FB_TRAFFICSIGNAL` 用 **ST** 编写信号分配算法（CASE 语句根据 STATUS 值输出灯状态），`FB_WAIT` 用 **IL** 编写延时控制。
- **结果**: SFC 使流程结构一目了然，ST 处理信号分配简洁高效，三种语言各取所长。

### 案例 2: 停车场管理 — CFC 数据流编程
- **问题**: 停车场系统需要处理入口/出口两个传感器的计数、闸机开门/关门时序、满位指示，涉及多个功能块的时序配合。
- **方法论的使用**: 使用 **CFC** 编程。计数器 `CTUD` 的输出直接连接到满位指示灯，`TP` 定时器控制 3s 闸机开启时间，`TOF` 定时器控制 10s 通行窗口。在 CFC 中设置数据流排序，确保计数器值更新后在同一周期内驱动满位指示判断。
- **结果**: 数据流驱动方式使信号处理链清晰可见，调试时能直观追踪每个信号的处理路径。

## E — 可执行步骤（Execution）

1. **决定语言选型（新模块）**
   - 判断模块的主要逻辑类型：
     - 算法/计算/数据处理 -> **ST**
     - 顺序控制/工序/状态机 -> **SFC**
     - 逻辑联锁/互锁/启停 -> **LD**
     - 功能块网络/信号链 -> **FBD** 或 **CFC**
     - 大规模自由放置功能块 -> **CFC**
   - 完成标准：每个模块选择了最适合其逻辑类型的编程语言

2. **编写 ST 语句**
   - 条件分支：`IF ... THEN ... ELSIF ... THEN ... ELSE ... END_IF;`
   - 多路分支：`CASE iState OF 1: ... 2: ... ELSE ... END_CASE;`
   - 定次循环：`FOR i := 0 TO 99 BY 1 DO ... END_FOR;`
   - 条件循环：`WHILE bRunning DO ... END_WHILE;` / `REPEAT ... UNTIL bDone END_REPEAT;`
   - 循环跳出：`EXIT;`（用于 FOR/WHILE/REPEAT 内部）
   - 完成标准：ST 代码编译通过，逻辑正确，无死循环风险

3. **调用函数和功能块（ST 中）**
   - 函数：`result := MyFUN(input1 := x, input2 := y);`
   - 功能块（三步）：
     - 声明实例：`fbMotor : FB_MotorControl;`
     - 调用：`fbMotor(start := bStart, speed := rSetSpeed);`
     - 读取输出：`bRunning := fbMotor.isRunning;` 或用 `=>` 连接
   - 完成标准：FUN 调用无状态依赖，FB 在声明区已实例化

4. **配置 CFC 执行顺序（如使用 CFC）**
   - 默认使用拓扑排序（坐标顺序）
   - 有数据依赖需求时切换为数据流排序（右键 -> 执行顺序 -> 数据流排序）
   - 手动微调：使用"置首"/"置尾"/设置执行顺序编号
   - 完成标准：CFC 执行顺序符合数据依赖关系，无反馈回路导致的竞争

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill
- 用户询问变量声明关键字（VAR/VAR_INPUT/VAR_OUTPUT 等）或匈牙利命名法前缀，应使用 **codesys-variable-system** skill
- 用户询问 POU 的类型选择或调用约束（FUN 不能调 FB 等），应使用 **codesys-pou-design** skill
- 用户询问任务配置（循环周期/优先级/看门狗），不使用此 skill
- 用户只需要 SFC 的详细语法（步/转移/限定符），SFC 是独立语言但本书中未包含专属 skill，可在此 skill 的参考矩阵中找到推荐
- 用户需要 IL 指令表的详细操作码清单（IL 为遗留语言，现代工程已较少使用）
